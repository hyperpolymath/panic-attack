https://github.com/metadatastician/standards/blob/9bdf864cc7f2c8e24b4df84bf00d04158eee3ad5/3-practice/PROOF-POLICY.adoc[`standards/3-practice/PROOF-POLICY.adoc`

== Where each kind of obligation belongs

* *Behaviour of first-party Rust code* (stripping, reachability, taint
  propagation, dispatch): Creusot with Pearlite contracts, and Verus, on the
  implementation (§1.2). An Idris2 model of a Rust function is not evidence
  that the function is correct (§1, §2.2).
* *Interfaces, ABI encodings and cross-language protocols* (the attestation
  chain, the C integer encodings): Idris2.
* *Statements true of any implementation* (for example, a taint lattice
  and its fixed point stated abstractly): Agda, rechecked in Rocq and Lean
  (§2).

No Kani obligation arises (§4.1). With `unsafe_code` forbidden,
`cargo clippy --lib --bins --tests --benches --all-features -- -F unsafe_code`
compiles at `f2a6a70eaec0cb02331e3264e05f185b5faab0f7`. The only `unsafe`
is in `examples/vulnerable_program.rs`, a deliberately buggy program that
exists to be scanned.

|Line-comment stripping is idempotent: `strip (strip s) = strip s`
|`src/abi/Stripping.idr`
|`PROVEN` (model)
|*Re-proved 2026-11-09.* The 2026-06-02 proof (issue #113) never
type-checked: its `+//+` case relied on reductions that do not hold for a
variable character, and it used `+decEq+` without importing it. The new proof
shows `+stripLineCommentsIdempotent+` (stripping twice equals stripping once)
through two facts: stripping is the identity on text with no `+//+`
(`+stripIsIdOnClean+`), and the strippers' output has no `+//+`
(`+stripIsClean+`/`+bodyIsClean+`, by mutual induction). `+bodyIsFixedPoint+`
follows. The strippers are restated with explicit `+Bool+` tests. An
exhaustive differential run over every string of length up to 9 on
`+{/, x, \n}+` (29,524 inputs) found no difference from the previous
definitions. A mutant that blanks with `+/+` instead of a space is rejected.
Nine closed sanity theorems, including two comments on different lines and
`+///+`.

The model does *not* match `strip_proof_comments`, so it is evidence about
the model only. It replaces comment characters with spaces and keeps every
newline. The Rust function deletes comment text and drops a trailing
newline: on `//x` the model gives three spaces and Rust gives the empty
string. The model also covers line comments only; block comments and string
literals are not modelled.

|Attestation chain: integrity, authenticity, non-repudiation
|`src/abi/AttestationUnforgeability.idr`
|`PROVEN` (model), relative to the `ASSUMED` hypotheses listed here
|The module's `parameters` block assumes:

* `chainCR`: the chain hash is *injective*.
* `sigCorrect`: an honest signature verifies.
* `sigBindsMessage`: a signature verifies only on the message signed.
* `sigOnlySigner`: for every verifying signature there is a secret key
  whose public key is the verifying key and whose signature on that digest
  is that signature.

`sigOnlySigner` says such a key *exists*. It says nothing about who
produced the signature, so `authenticity` inherits that limit: it shows the
seal equals one a matching key would make, not that the key holder made it.
`chainCR` and `sigOnlySigner` are idealisations, stronger than collision
resistance and EUF-CMA, and false of any real fixed-length hash or
signature scheme. So these are theorems of a symbolic (Dolev-Yao style)
model, not a computational security reduction. Model to
`src/attestation/`: `ASSUMED`. A computational proof is not claimed.

Routing is not coverage: `Language::Unknown` goes to `InputAdapter`, and a

This replaces the Idris2 `PatternCompleteness.idr`, which was vacuous
(`GenericAnalyzer` inhabited its witness for every language), stale (50 of

  are not affected.

fixed; it does not discharge them. The model's own remaining slices
