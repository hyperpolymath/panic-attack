= Proof status: panic-attack

This file records each proof obligation in panic-attack, the verifier it
belongs to, and its status. The rules are the estate proof policy,
https://github.com/metadatastician/standards/blob/9bdf864cc7f2c8e24b4df84bf00d04158eee3ad5/3-practice/PROOF-POLICY.adoc[`standards/3-practice/PROOF-POLICY.adoc`
at `9bdf864cc7f2c8e24b4df84bf00d04158eee3ad5`]. Statuses use its closed §5
vocabulary: `PROVEN`, `PROVEN-WITH-AXIOMS`, `TESTED`, `ASSUMED`, `OPEN`.

None of these obligations is a theory theorem (§1), so none carries a Proof
Witness Grade.

== Where each kind of obligation belongs

* *Behaviour of first-party Rust code* (stripping, reachability, taint
  propagation, dispatch): Creusot with Pearlite contracts, and Verus, on the
  implementation (§1.2). An Idris2 model of a Rust function is not evidence
  that the function is correct (§1, §2.2).
* *Interfaces, ABI encodings and cross-language protocols* (the attestation
  chain, the C integer encodings): Idris2.
* *Statements true of any implementation* (for example, a taint lattice
  and its fixed point stated abstractly): Agda, rechecked in Rocq and Lean
  (§2).

No Kani obligation arises (§4.1). With `unsafe_code` forbidden,
`cargo clippy --lib --bins --tests --benches --all-features -- -F unsafe_code`
compiles at `f2a6a70eaec0cb02331e3264e05f185b5faab0f7`. The only `unsafe`
is in `examples/vulnerable_program.rs`, a deliberately buggy program that
exists to be scanned.

== How the Idris2 modules are checked

The modules live at `src/abi/PanicAttack/ABI/<M>.idr`, so each path matches
its module name, and `src/abi/panic-attack-abi.ipkg` lists them all.

* *Gate:* the `abi-proofs` job in `.github/workflows/proven-tests.yml` runs
  on every pull request and on pushes to `main`:
  `idris2 --typecheck src/abi/panic-attack-abi.ipkg`. A pass is exit 0
  *and* no `Error:` line, because `idris2 --check` can exit 0 while printing
  an error. Its toolchain is Idris2 0.7.0 from the same pinned installer and
  cache as the framework job. Each green run of that job is the current
  receipt; a failing run revokes the statuses below.
* *Negative controls* for the package route: a planted false lemma and a
  planted missing import each make it exit non-zero with an `Error:` line.
* *Hygiene:* every module sets `%default total` and uses no `believe_me`,
  `assert_total`, `postulate` or holes.

First receipt, before the gate existed: Idris2 0.7.0, built from tag
`v0.7.0` (`27780073c8631826d846499840b3857d9b9a4fd5`) on Chez Scheme 9.5.8,
over `src/abi/*.idr` at `3dc4728762f37c1e5bebdb988783c7683c50fb55`. Each
module was checked from a module-shaped copy of the tree. All five passed,
and a planted false lemma and a planted non-terminating definition in
`Stripping.idr` were both rejected.

|`PROVEN` (model), relative to the `ASSUMED` hypotheses listed here
|The module's `parameters` block assumes:

* `chainCR`: the chain hash is *injective*.
* `sigCorrect`: an honest signature verifies.
* `sigBindsMessage`: a signature verifies only on the message signed.
* `sigOnlySigner`: a verifying signature was produced by the key holder,
  with no exceptions.

`chainCR` and `sigOnlySigner` are idealisations. They are stronger than
collision resistance and EUF-CMA, and false of any real fixed-length hash
or signature scheme. So these are theorems of a symbolic (Dolev-Yao style)
model, not a computational security reduction. Model to
`src/attestation/`: `ASSUMED`. A computational proof is not claimed.

|Every language reaches an analyzer; every weak-point category has a

|`src/abi/PanicAttack/ABI/PatternCompleteness.idr`
|`PROVEN` (model); supports no claim about the Rust code
|The theorem is vacuous: `GenericAnalyzer : HasAnalyzer lang` inhabits
the witness type for every language, so it holds whatever the dispatch
does. The guarantee it was meant to give already holds in Rust:
`match file_lang` in `src/assail/analyzer.rs` ends in
`_ => analyze_generic`, and `rustc` checks the match is exhaustive.

The model has also drifted. Its `Lang` has 50 constructors and
`src/types.rs` has 52; `C` and `Php` are missing. `crossLangAlwaysApplied`
says cross-language checks run on every file, but the Rust code skips them
when `configuration.is_some()`. That model claim is false of the
implementation.
